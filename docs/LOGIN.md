# Shared login presentation (1.3 preview)

Hosts opt in with `data-core-login` on a `main`, `section` or other container. Use a `.kn-core-login-card` containing `.kn-core-login-heading` and `.kn-core-login-content`. An optional `.kn-core-login-provider` contains the host's anchor or button with `data-core-login-provider` and the label **Login with KagNode**. The server adapters provide the same structure as the `login-frame` template with `product`, `heading`, `description`, `content` and `provider` slots. Slots are trusted, already escaped authorized markup, as with existing templates. Escape product text for both HTML text and attributes.

Keep existing local forms, validation, CSRF, authorization and local password or vault-unlock steps. Omit the provider slot when the administrator has disabled the connection. Core supplies presentation only: the host must choose an authorized local initiation route and own its pending, cancellation and error handling. Use `data-core-login-status` with `role="status"` for progress/cancellation and an appropriate alert for errors. A button may initiate a CSRF-protected POST; an anchor may navigate to an authorized local route. Never put secrets, exchange results or remote tokens in markup or URLs.

The adapter bundles this CSS with the application's local Core assets. No browser request to GitHub is needed. The shared frame works without JavaScript, preserves local login when the issuer is unavailable, uses 8px controls and 12px cards, and does not add animation.

For account menus, supply an authorized `#account-menu` or `[data-core-menu-content]` containing the host's permitted actions. Otherwise Core creates an identity, account/preferences link and existing lock/sign-out action. Set `data-core-settings` on `body` to the host's actual settings destination. `KagNodeCore.setSession({authenticated, subject, name, email})` updates the generated identity on the next open. Profile/account synchronization remains a host responsibility. Never send private destinations to unauthorized clients.

`KagNodeScroll.refresh(container)` optionally limits discovery to a changed subtree; omitted containers retain full-document discovery. Refreshes are batched on the next animation frame. Existing regions repaint together, preserving native scrolling and rails; no waiting timer is inserted. Core's sidebar uses scoped refreshes because its changes do not require rediscovering unrelated page content.

## Optional connection controller

Apps that want the shared code/approval/cancel presentation provide `window.KagNodeLoginHost` with synchronous `state(): {enabled: boolean}`, async `request(action, data)` and async `complete(result)`. The controller is delegated and supports late host initialization; call `KagNodeLogin.refresh()` or dispatch `kagnode:login-ready` when cached state changes. It only binds buttons with `data-core-login-provider` inside a login container with a `data-core-login-status` output. Anchors retain ordinary navigation.

`request('start', {})` returns `{pending: true, attempt_id, user_code, verification_uri, interval, expires_in}`. Core displays the user code as text and the HTTPS verification link, then calls `request('status', {attempt_id})` at the bounded interval. Pending responses continue polling; `{authorized: true, ...}` is passed intact to `complete(result)`. The host owns the signed-in, local-unlock or setup continuation. Completion disables another start on that button. The host can call `KagNodeLogin.reset(buttonOrContainer)` to clear that completion and status when returning from local unlock/setup to login; reset cancels an active attempt, ignores its late results and rechecks cached enabled state. Cancellation calls `request('cancel', {attempt_id})`, restores focus and ignores late results. Polling expires after the host lifetime (at most ten minutes), uses intervals from one to thirty seconds, and stops on page exit. Timeout, reset and page exit best-effort cancel a known attempt through the host adapter; the backend must still enforce its own expiry. Failed requests present a retry/local-login message without exposing exception details.

The host request adapter owns CSRF, authorized local endpoints and interpretation of backend errors. Attempt identifiers are local opaque handles. Device proofs, exchanged authorization, refresh credentials and account tokens stay on the backend. `state()` only controls presentation; backend authorization remains authoritative. Provider cancellation does not modify the existing local form.
